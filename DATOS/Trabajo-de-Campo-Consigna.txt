Trabajo de Campo Integrador

Materia: Ingeniería de Software II
Cuatrimestre: 2026 — IUA
Modalidad: Grupal (3-4 personas)
Duración: 7 semanas (29/04 al 16/06)
Peso en la calificación final: consultar régimen vigente

Objetivo

Aplicar los conceptos vistos a lo largo de toda la materia (Temas I a VIII) sobre un proyecto de
software propio, desde su concepción hasta su evaluación. Al finalizar el trabajo, cada grupo
debe poder demostrar:

• Un sistema de software funcional con calidad medible

• Un plan de calidad (SQA) que documente cómo se aseguró la calidad durante el desarrollo

• Una matriz de trazabilidad (RTM) que vincule requerimientos, código y tests

• Métricas de código y reportes de pruebas

• Wireframes/prototipos del frontend

• Defensa oral del proyecto

Conformación de grupos

• Tamaño: 3 a 4 integrantes (excepciones consultar con docente).

• Cuándo: se conforman en la clase del miércoles 29/04 (Sem 7).

• Responsabilidades: cada grupo designa un referente que coordina entregas con el docente.

Tipos de proyectos sugeridos

Cualquiera de los siguientes (el grupo puede proponer otro a aprobación del docente):

Restricciones de alcance

• LOC objetivo: entre 800 y 3000 líneas de código (sin contar dependencias).

• Funcionalidades mínimas: al menos 5 requerimientos funcionales documentados.

• Persistencia: debe haber alguna forma de almacenamiento (base de datos, archivos, API
externa).

• Stack tecnológico: libre (Python, JavaScript/TypeScript, Java, Go, Ruby, etc.). El docente
debe poder ejecutar el proyecto siguiendo el README.

Reglas operativas

1. Repositorio público obligatorio en GitHub o GitLab desde el Hito 2. El docente debe tener
acceso de lectura.

2. Commits regulares: cada integrante debe tener commits propios. No se acepta "todo el
código en un commit final".

3. Mensajes de commit descriptivos: evitar fix , update , cambios . Usar formato [REQ-
F01] Implementa registro de pacientes .

4. README completo: instalación, requisitos previos, comandos para ejecutar tests y el
sistema.

5. No se permite código copiado sin atribución. Las dependencias externas (librerías) están
permitidas pero deben declararse.

6. Reuniones de seguimiento: el docente puede solicitar reuniones de 15 min con cada grupo
entre hitos.

Tips de un docente que ya vio muchos trabajos de campo

1. Empiecen ya. Las primeras 2 semanas se sienten lejanas, pero son las que más rinden.

2. Documenten desde el primer commit. Trazabilidad embebida es 10x más fácil que
reconstruirla al final.

3. No se enamoren del alcance. Recortar es difícil pero necesario. Mejor 5
funcionalidades pulidas que 15 a medias.

4. Hagan code review entre ustedes. Es práctica real de Tema II y mejora la calidad sin
esfuerzo extra.

5. Tests primero, defectos después. Si encuentran defectos sin tests asociados,
agreguen el test antes de arreglar.

6. El parcial 2 cubre Temas V-VIII. El trabajo de campo aplica TODO. Estudien con su
propio proyecto.
